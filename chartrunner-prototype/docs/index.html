ChartRunner SDK v0.9.64

A gamified trading SDK on Solana, built on three pillars — gamification, education, on-chain (industry-standard). Six in-game primitives (bracket, OCO, ladder, hedge, radar, rescue), four Anchor programs, and a four-partner ecosystem stack — Phoenix for trades, MagicBlock for matches, Honeycomb for the economy, Pyth for the truth.
Two minutes from cold start to running a chart. Wallet-first login → on-chain leaderboard → real Solana RunRecord PDAs minting from inside the game. Every primitive learned in the game is the same SDK call that lives in production.

Overview

ChartRunner is a gamified trading SDK that lets new traders learn through play. Each in-game gesture (a bracket, an OCO, a ladder fill) maps 1:1 to an SDK call shape that lives in production. The runtime composes:

  • A canvas game — an HTML prototype that runs on real chart candles, with bear monsters, an upside-down world, and six trading primitives wired as in-game abilities.
  • An on-chain layer — three Anchor programs covering map storage, run records, and realtime multiplayer match state.
  • Three live ecosystem partners for trades (Phoenix Rise), matches (MagicBlock Ephemeral Rollups), and economy (Honeycomb).

Quickstart

Two paths — pick the one that fits where you are.

Just play

Open chartrunner.xyz, click Enter Run, connect a Solana wallet (Phantom / Backpack / Solflare), play. Your run is committed to the on-chain leaderboard at game-end via chartrunner_registry::record_run.

Build on the SDK

# clone the prototype repo
git clone https://github.com/chartrunner/chartrunner.git
cd chartrunner

# install the wallet bridge
cd solana-connect && npm install && npm run build

# open the prototype locally
open ChartRunner_Prototype.html

Primitives

Six in-game abilities, each a real SDK call. Compose them into the same flows you'd run on Phoenix or any orderbook.

PrimitiveSDK callHotkeyWhat it does
Bracketsdk.placeBracket({ side, entry, stop, target })3 → bracketEntry + stop + target as one atomic ladder
OCOsdk.placeOCO({ side, a, b })3 → ocoTwo orders, one cancels the other
Laddersdk.placeLadder({ side, levels[] })3 → ladderScale-in / scale-out at N price levels
Hedgesdk.placeHedge({ asset, ratio })3 → hedgeOpen the offset against an existing position
Radarsdk.armRadar({ levels })2 → radarAlert when price taps a level — no order until armed

chartrunner_match scaffold

Realtime PvP match state. A MatchState PDA holds the asset, timeframe, the participants (up to 8), their live positions and scores. The host calls delegate_match to transfer ownership to the MagicBlock delegation program — after which every tick_player instruction settles on the Ephemeral Rollup at sub-millisecond latency, zero fee. 

pub fn init_match(ctx: Context<InitMatch>, nonce: u64,
                 asset: [u8; 16], timeframe: [u8; 8],
                 max_players: u8) -> Result<()>
pub fn delegate_match(ctx: Context<DelegateMatchInput>, nonce: u64) -> Result<()>
pub fn tick_player(ctx: Context<TickPlayer>,
                  x: i32, y: i32, score_delta: u64) -> Result<()>
pub fn commit_match(ctx: Context<CommitMatch>) -> Result<()>
pub fn commit_and_finish(ctx: Context<CommitMatch>) -> Result<()>

chartrunner_oracle scaffold

Verifiable price-feed primitive backed by Pyth Core. Wraps the Pyth pull-oracle pattern — the client posts a Hermes VAA to a PriceUpdateV2 account, then verify_price reads it via pyth-solana-receiver-sdk, enforces a 30-second freshness gate, and writes a PriceCertificate PDA seeded by (payer, feed_id_hex). chartrunner_registry::record_run and chartrunner_match::tick_player cite the certificate to make scores forge-resistant. 

pub fn verify_price(ctx: Context<VerifyPrice>,
                    feed_id_hex: String,
                    max_age_sec: Option<i64>) -> Result<()>
pub fn read_certificate(ctx: Context<ReadCertificate>) -> Result<()>

Phoenix Rise live partner

Phoenix Rise is the live-trading partner. Every in-game primitive routes to a real Phoenix perpetual order via @ellipsis-labs/rise. Orders are wrapped with the Phoenix Flight builder layer so ChartRunner accrues fee_bps on every routed instruction — no marketplace UI required for revenue. 

import { buildBracketTx } from './lib/phoenix-rise';

const tx = await buildBracketTx({
  trader: wallet.publicKey,
  market: 'BTC-PERP',
  side:   Side.Bid,
  entry:  68_420n,
  stop:   67_900n,
  target: 69_400n,
  qty:    1n,
  flightBuilder: CHARTRUNNER_BUILDER_AUTHORITY,
  flightFeeBps:  CHARTRUNNER_FLIGHT_FEE_BPS, // 25 = 0.25%
});

Adapter at solana-connect/src/lib/phoenix-rise.ts. Endpoints: https://perp-api.phoenix.trade, https://api.mainnet-beta.solana.com.

MagicBlock Ephemeral Rollups live partner

Two players running on the same chart in real time isn't possible at Solana's base-layer 400 ms slot times. Ephemeral Rollups solve this — the MatchState PDA gets delegated to MagicBlock's ER validator, where every player's tick_player settles in ~1 ms at zero fee. Every 30 s the rollup commits state back to base layer for verifiability; commit_and_finish undelegates so the final state lives on Solana forever. 

import {
  createEphemeralConnection,
  submitErTransaction,
} from './lib/magicblock-ephemeral';

const er = createEphemeralConnection(); // devnet-as.magicblock.app
await submitErTransaction(er, wallet, tickPlayerIx);

Adapter at solana-connect/src/lib/magicblock-ephemeral.ts. Endpoints: https://devnet-as.magicblock.app/, wss://devnet-as.magicblock.app/. Validator: MAS1Dt9qreoRMQ14YQuhg8UTZMMzDdKhmkZMECCzk57 (devnet).

Honeycomb is the gamification axis of the four-partner stack — Phoenix is for trades, MagicBlock is for matches, Pyth is for truth, Honeycomb is for player progression. The under-told story — cross-game portability

A Honeycomb Character earned in ChartRunner is the same Character in any other Honeycomb-integrated Solana game. A Bronze trader in ChartRunner starts elevated in the next game on the network. We get that network effect for free by adopting Honeycomb's primitives instead of inventing our own. ChartRunner positions as the credentials engine for Solana-native trading skill — Honeycomb gets a flagship game with real trader pedigree on its Character schema; we get our Character to have utility outside our own product.

Concrete on-chain flips begin at M1 (tokenomics paper). The Frontier pitch leads with gamification + education + on-chain, not "we already minted 10,000 NFTs."

Pyth Core scaffold

Pyth fills the one slot the other three partners assume: the price the score was computed against is provably real. Today, ChartRunner pulls candles from Binance REST and the client signs over the resulting score — fine for replay, not honest at scale. Pyth Core closes that loop. chartrunner_oracle accepts a fresh Pyth update via the receiver SDK's pull pattern, enforces a 30-second freshness gate, and writes a PriceCertificate PDA the registry and match programs cite on-chain. A forged score now requires forging Pyth's signed VAA — i.e. forging Wormhole guardian signatures, which is the same security model as Pyth itself.

Live tape — Hermes streaming

import { streamPyth, PYTH_FEED_IDS, pythPriceToFloat }
  from './lib/pyth-feeds';

const dispose = streamPyth(
  [PYTH_FEED_IDS.BTC_USD, PYTH_FEED_IDS.ETH_USD, PYTH_FEED_IDS.SOL_USD],
  (p) => updateHud(p.feedId, pythPriceToFloat(p)),
);
// …~400 ms cadence per feed, no wallet needed

On-chain verify — atomic post + verify

import { postPriceUpdateAndVerify } from './lib/pyth-feeds';

const tx = await postPriceUpdateAndVerify({
  conn,
  payer:      wallet.publicKey,
  feedSymbol: 'BTC_USD',
});
await wallet.sendTransaction(tx, conn);
// PriceCertificate PDA now exists and `record_run` can cite it
